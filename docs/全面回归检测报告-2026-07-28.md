## 2. 高优先级问题

### P1-1：静态图片作为画中画背景时处理不会自动结束

有效图片背景使用 `-loop 1` 形成无限输入，但输出命令没有时长限制、`-shortest` 或 overlay 最短输入结束规则。

实测 3.018 秒输入运行 64 秒后仍未结束，已人工终止 FFmpeg。继续运行会不断占用 CPU、磁盘和时间。

证据：`processor/batch_params_processor.py:2875-2877`、`processor/batch_params_processor.py:3118-3119`。

### P1-2：动态缩放会成倍放大视频时长

`zoompan` 的 `d` 被设置为“视频时长 × FPS”，该值会应用到每一个输入帧，而不是整段视频。

实测 0.4 秒、25 FPS 视频输出为 4.0 秒，放大 10 倍。按当前公式，3 秒视频可能被扩展到约 225 秒，长视频可能造成极长处理时间和巨大输出文件。

证据：`processor/batch_params_processor.py:1031-1047`。

### P1-3：正式处理启用渐出时 FFmpeg 必然失败（已修复）

正式处理生成 `fade=out:st=duration-0.3:d=0.3`。内置 2018 FFmpeg 不支持在 `st` 中使用 `duration-数值` 表达式。

真实报错：`Unable to parse option value "duration-0.3" as duration`。

证据：`processor/batch_params_processor.py:1529-1538`。

### P1-4：批处理线程仍未接入多项输出与批处理选项

当前运行时使用拆分后的 `processor.batch_video_runner.process_batch`，输出路径只使用输出目录和原文件名。

以下配置未应用：目标格式、删除文件名文本/正则、添加编号、已完成跳过、同名文件策略、独立文件夹、原目录结构、子目录处理和并行任务。

实测输入 MOV 并指定目标格式 MP4 后，输出仍保留 `.mov`；删除文本和添加编号也没有生效。

证据：`processor/batch_video_runner.py:20-27`、`ui/batch_video/main_window.py:2965-2977`。

### P1-5：完成后的移动/删除动作可能作用于本轮未勾选文件

线程只处理本轮勾选队列，但完成回调遍历整个表格，将所有状态仍为 `done` 的行加入后处理。若某个未勾选文件是上一轮完成状态，本轮启用“移动到原目录”或“删除原文件”时，可能再次对它执行移动或删除。

这是潜在数据损失风险。本轮未执行真实删除测试，只进行了代码路径核对。

证据：`ui/batch_video/main_window.py:4324-4329`、`ui/batch_video/main_window.py:4367-4435`。

## 3. 中优先级问题

### P2-1：分段变速输出时长错误

视频分段 `trim` 后直接执行 `setpts=倍率*PTS`，没有先减去 `STARTPTS`；第二段及后续分段保留原始时间偏移。

实测 3.018 秒输入、0.9～1.1 倍变速，理论输出约 2.9 秒，实际输出 5.92 秒。

证据：`processor/batch_params_processor.py:3191-3227`。

### P2-2：抽帧后视频与音频时长不一致，“声音变速”无效（已修复）

每 5 帧抽 1 帧后，视频流时长为 0.600 秒，音频仍为 3.018 秒，后段会停留在最后一帧。

勾选和不勾选“声音变速”生成的命令完全一致，均没有 `-af`，说明 `frame_extract.audio_speed` 未接入处理器。

证据：`processor/batch_params_processor.py:1049-1062`、`ui/batch_video/main_window.py:3321-3333`。

### P2-3：图片背景无效或被删除时会生成空滤镜图

画中画开关启用后，代码无条件进入 `filter_complex` 路径。背景文件不存在时没有构建任何滤镜，却仍输出 `-filter_complex ""`，FFmpeg 报 `No such filter: ''`。

证据：`processor/batch_params_processor.py:2866-2882`、`processor/batch_params_processor.py:2933-3008`。

### P2-4：全部 LUT 的 QImage 后备预览会阻塞界面

FFmpeg 预览失败时，31 个 LUT 在主界面线程逐像素计算。实测耗时 13.348 秒，期间界面无法响应。

正常 FFmpeg 路径已通过，该问题只在 FFmpeg 启动失败、返回失败或输出无效时触发。

证据：`ui/lut_filter_dialog.py:499-539`、`ui/lut_filter_dialog.py:623-666`。

### P2-5：处理完成统计使用整个列表，不是本轮勾选队列

本轮只勾选部分视频时，完成日志中的总数、成功数和失败数仍遍历整个表格，可能包含之前批次状态。

证据：`ui/batch_video/main_window.py:4324-4353`。

## 4. 低优先级问题

### P3-1：马赛克改变输出分辨率

实测 320×240 输入启用马赛克后输出为 312×240。原因是先进行整数缩小，再以缩小后的 `iw` 乘回马赛克尺寸，不能恢复原宽度。

证据：`processor/batch_params_processor.py:1600-1605`。

### P3-2：相对输入路径错误后仍提示全部处理完成

相对输入路径且输出目录为空时，第一项报“输出目录无效”并提前退出，第二项未处理，但最终进度仍为 100%，提示“全部处理完成”。

证据：`processor/batch_video_runner.py:101-108`、`processor/batch_video_runner.py:150-154`。
